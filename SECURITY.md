# Security Policy

## Supported Versions

| Version | Supported          |
| ------- | ------------------ |
| pre-1.0 | ✅ (pre-release)   |

This project is currently in pre-release development. Security fixes are applied to the `main` branch.

## Reporting a Vulnerability

**Please report security vulnerabilities privately.**

**Contact:** ashmeet.singh.talwar1@gmail.com

When reporting, please include:
- Description of the vulnerability
- Steps to reproduce
- Potential impact
- Any suggested mitigations

We will acknowledge receipt within 48 hours and provide a timeline for a fix.

## Scope

This policy covers:
- The core application code (Rust, Java, Python, TypeScript)
- Protobuf contracts (`proto/`)
- Infrastructure configuration (`docker-compose.yml`, `infra/`)
- CI/CD pipelines (`.github/workflows/`)

Out of scope:
- Third-party dependencies (report upstream)
- Local development environment issues

## Paper Trading Disclaimer

**This is a paper trading platform only.** No real money, no custody, no order routing, no brokerage credentials. All trading is simulated. The UI and all charts are labeled **simulated / backtested; not investment advice**.

This project is educational and does not constitute a broker/dealer or investment adviser function. In India, giving investment advice or running trading services is regulated by SEBI; keep the product educational and do not market backtest results as predictions of returns.

## Security Practices

- No secrets in git (enforced by gitleaks in CI and pre-commit)
- No default passwords (all generated by `./scripts/bootstrap.sh`)
- All ports bound to 127.0.0.1 in local development
- Non-root containers with minimal base images
- JWT access tokens (15 min, EdDSA, `kid` rotation)
- Refresh tokens (opaque, SHA-256 stored, rotate on use, reuse detection)
- Per-user data isolation (`user_id` filter in every query)
- Rate limiting on all public endpoints
- Audit logging of security events
