# DevOps, Docker, CI and free hosting

Spec: `docs/12-DEVOPS-DEPLOYMENT.md`. Constraint: **free to build and run**; local-first.

## Docker Compose
- Use **profiles**: `core` (Postgres, Redis), `analytics` (ClickHouse), `obs` (Prometheus, Grafana, optional Alertmanager), `bus` (optional Redpanda/NATS, off by default), `app` (feed, api, research, web).
- Healthchecks on every service; `depends_on: condition: service_healthy`; named volumes; an internal network; publish only the ports needed (web/proxy, and DB ports bound to `127.0.0.1` in dev).
- Credentials come from `.env` generated by `scripts/bootstrap` (random dev secrets, JWT keypair). **No default passwords committed.** `.env.example` documents all variables.
- Resource limits on the demo VM (`deploy.resources` or `mem_limit`/`cpus`); restart policies.
- Grafana/Prometheus configs and dashboards are provisioned from `infra/` files (no manual clicking).

## Dockerfiles (multi-stage, small, non-root)
- **Rust feed:** build stage with `cargo-chef` for dependency caching; release build; runtime `debian:stable-slim` or distroless (`cc`); non-root user; `HEALTHCHECK` on the health port.
- **Java API:** build with Gradle/Maven wrapper (cache layers); runtime Temurin 21 JRE slim; non-root; container-aware JVM flags (`-XX:MaxRAMPercentage`), explicit GC choice; layered jar.
- **Python research:** build the PyO3 wheel with maturin in a builder stage; runtime `python:3.12-slim` with the wheel installed; non-root.
- **Next.js:** `output: "standalone"`; Node slim runtime; non-root; only needed files copied.
- Pin base images (digests for releases); no secrets in layers or build args; `.dockerignore` for each context; scan with Trivy; produce SBOMs.

## CI/CD (GitHub Actions)
Workflows: `proto` (buf lint/breaking), `rust` (fmt, clippy, tests, audit/deny, bench smoke, wheel), `java` (build, tests with Testcontainers, dependency check), `python` (ruff, mypy, pytest, pip-audit, parity with wheel), `web` (lint, typecheck, Vitest, build, bundle size), `e2e` (nightly compose + Playwright), `bench` (manual/weekly), `security` (gitleaks, Trivy), `release` (tags: images, SBOM, changelog).
Practices: path filters; dependency caches (Cargo, Gradle, pip, npm); required status checks on `main`; reusable workflows; least-privilege `permissions:` on every workflow; pin third-party actions by SHA; no secrets in forked PR workflows.

## Configuration
12-factor: env vars with prefixes (`SB_FEED_`, `SB_API_`), typed config validation at startup, fail fast on missing values; Spring profiles `dev`/`demo`; Rust TOML + env overrides; Next.js `NEXT_PUBLIC_*` only for non-secrets.

## Free hosting for a demo (**verify current terms before relying on any option**)
1. **Local + recorded demo video** - safest; best for latency numbers.
2. **Oracle Cloud Always Free VM** - run compose (feed + api + web + DBs); check region capacity, resource limits, and reclamation policies.
3. **Cloudflare Pages / Vercel free** for static/serverless Next.js pages (not for long-lived WebSockets; the WS endpoint lives on the VM).
4. **Cloudflare Tunnel** to expose a home machine.
Demo mode: read-only market views + rate-limited sandbox trading (or invite-only); aggressive per-IP limits; backtest quotas. TLS via Caddy/Nginx with automatic certificates; internal services never published.

## Backups and recovery
Nightly encrypted `pg_dump` to off-host storage; weekly restore test; configs/dashboards in git; event logs are not backed up beyond curated fixtures; write runbooks (feed restart, DB restore, key rotation, redeploy) in Phase 8.

## Cost guardrails
No paid dependency without an ADR; verify free tiers cannot auto-convert to paid billing; set budget alerts where available.

## Anti-patterns
Running as root in containers; `latest` tags in releases; secrets in compose files or images; exposing DB/Redis/gRPC publicly; CI that requires paid runners; unpinned actions; manual dashboard configuration that isn't in git.

## Review checklist
- [ ] Healthchecks, non-root users, pinned images
- [ ] No secrets committed; `.env.example` updated
- [ ] CI path filters and caches configured; permissions minimal
- [ ] Profiles keep the minimum stack runnable on a laptop
- [ ] Hosting claims verified against current provider terms
